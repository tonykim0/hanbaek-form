# Claude Code 시작 프롬프트

> ★역사 문서★ 2026-08 착수 때 한 번 쓰인 시작 프롬프트다. 「노션이 백엔드다」는 그 시점
> 이야기이고, 지금 콘솔의 정본은 자체 Postgres 다. 현재 규칙은 `CLAUDE.md` 를 본다.

아래를 Claude Code 첫 메시지로 붙여넣으세요. (hanbaek-form repo를 clone 한 폴더에서 실행)
같은 폴더에 `SYSTEM_ARCHITECTURE.md`와 `INTAKE_SPEC.md`를 함께 두세요.

---

이 저장소는 한백 EV의 내부 업무 포털(Next.js on Vercel)이다. 이걸 확장해서 EV 충전 사업의
**접수 → 시공 → 정산 전체를 관리하는 웹앱**으로 만들려 한다.

**현재 상태**: 접수를 받으면 Anthropic API(Claude Console 연동)로 자동분류해서 **노션에 저장**하고 있다.
즉 지금 노션이 백엔드다. **웹앱이 완전해질 때까지 노션을 병행 유지한다** — 지금 돌아가는 걸 부수지 마라.
최종적으로(맨 마지막 단계에서만) 노션을 자체 DB로 대체한다.

첨부 문서:
- `SYSTEM_ARCHITECTURE.md` — 최상위 사양. 특히 §0-1(노션 병행·추상화 계층 전략)과 §3(공정→정산 트리거).
- `INTAKE_SPEC.md` — 1단계(접수)의 상세.
- `PRICING_MATRIX.md` — 단가 매트릭스 실측 데이터(운영사별 단가 + 기성 트리거).

**아직 코드는 쓰지 마라.** 먼저 파악하고 계획을 보고하라.

1. **저장소 구조 파악 — 특히 노션 연동 코드가 최우선**
   - **API route를 찾아 읽어라**(`app/api/*` 또는 `pages/api/*`): 접수 시 노션의 어느 DB/속성에 무엇을 쓰는가?
   - **자동분류 로직**: 무슨 프롬프트로 Anthropic API를 호출하고, 파일을 어떻게 분류해 노션 어디에 넣는가?
     (노션 현장 페이지의 `01_` `02_` 번호 붙은 첨부가 이 자동분류 결과물인지 확인)
   - 노션 API 래퍼/클라이언트가 어디 있는지, 인증 토큰을 어떻게 관리하는지
   - `/intake`, 운영사별 계약서 페이지, `/materials`, `/charger-history`, `/kapt`, `/notices/*` 각각의 역할
   - 인증에 역할 구분이 있는지, 상태관리·스타일링은 무엇인지

2. **파악 결과 보고 후, 아키텍처를 제안**
   - `SYSTEM_ARCHITECTURE.md` §0-1의 **추상화 계층**을 어떻게 만들지: 논리 스키마(§6)를 인터페이스로 정의하고
     그 뒤를 **지금 노션 API 구현**으로 채우는 구조. (나중에 Postgres 구현으로 바꿔 끼울 수 있게)
   - §3 **공정→정산 트리거**를 어떻게 구현할지 (노션 수식이 이미 하는 부분 vs 앱에서 할 부분 구분)
   - 서류 조건부 규칙(INTAKE_SPEC §3)과 역할 권한(§5)을 어디에 둘지
   - audit_log(협력사 입력추적)는 노션에 없으니 어떻게 남길지

3. **구현 로드맵 확정** — `SYSTEM_ARCHITECTURE.md` §7 Phase 0~6을 저장소 사정에 맞게 조정.
   지금은 Phase 0(파악·추상화 설계·골격)만.

핵심 제약:
- 새 의존성 최소화. 기존 스택 재사용. **기존 노션 연동·자동분류 코드를 최대한 재사용.**
- **접수/시공/정산을 따로 만들지 마라. 하나의 project를 공유하는 통합 모델로 짜라.**
  나중에 시공·정산 붙일 때 접수를 엎지 않도록, 처음부터 전체 데이터 모델을 세우고 접수부터 구현.
- **노션은 병행 유지. 지금 노션이 정본이다.** 노션 데이터를 지우거나 덮어쓰지 않는다.
  데이터 접근을 추상화 계층으로 감싸서, 지금은 노션 구현으로 채우고 나중에 DB로 교체(§0-1).
- **dual-write 금지**: 한 필드를 노션과 다른 곳에 동시에 쓰지 않는다.
- 서류는 종류(key)로 다룬다. 계약은 현장당 복수 라인, 단가는 라인별.
- `*` 접두 노션 속성은 API 조회 불가. null ≠ 빈값. 환경부 마감일은 없음(임의 생성 금지).

먼저 1번(파악)만 하고 결과를 보고해라. **특히 노션 연동·자동분류 코드가 지금 정확히 뭘 하는지**가
가장 중요하다. 그걸 알아야 추상화 계층을 어떻게 짤지 정해진다. 그다음 함께 아키텍처를 확정한다.
