# 한백 EV 계약서 접수 시스템 — 구현 사양

> ★역사 문서★ 2026-08 착수 시점의 사양이고, 접수는 구현됐다. **정본은 코드다**:
> 서류 종류·조건부 필수 규칙은 `lib/doc-rules.ts`, 접수 폼은 `components/IntakeForm.tsx`,
> 자동분류는 `lib/intake-auto.ts`·`lib/prompts.ts`. 이 문서의 표와 어긋나면 코드가 맞다.

## 0. 결정 사항 (먼저 읽을 것)

- **repo: 기존 `hanbaek-form`에 얹는다. 새 repo 안 만든다.** 접수는 `/intake` 페이지의 고도화이고,
  기존 포털의 운영사별 계약서·자료실·charger-history·notices 양식과 링크로 엮인다.
- **현재 `/intake`**: ZIP 1개 + 소속/이름/특이사항만 받음 → 접수 후 한백이 노션에 현장정보를 재입력.
  **이 이중입력을 없애는 게 목표.** 접수 시점에 기본사항+실사정보+계약사항을 다 받는다.
- **노션 병행**: 즉시 컷오버 아님. 노션과 나란히 테스트로 운영. (그래서 별도 repo 금지 — 나란함 유지)
- **단가 규칙은 한백만 지정**. 지정 전까지 영업사는 금액을 못 본다. 지정 후 영업비·시공비 공개.

## 1. 역할 (권한)

| 역할 | 볼 수 있는 것 |
|---|---|
| 관리자(한백) | 전부. 원가/마진 포함. 단가 규칙 지정 권한 |
| 영업+시공 협력사 | 자기 현장, 자기 영업비+시공비 |
| 시공만 | 시공비만 (영업비 숨김) |
| 영업만 | 영업비만 |

- 겸업사(영업+시공): 에코일렉, 대상전력, 이에프이노베이션, 제일전기통신, 네이비인프라
- 원가/마진 필드(자재비, 한전불입금, 감리비용, 전안수수료, 턴키단가, 지급정책, 기성 계획액)는
  **모든 협력사에게 숨김**. 한백만.

## 2. 접수 폼 입력 필드

### 기본사항 (노션 계약/현장관리 마스터)
- 운영사* (플러그링크 / 나이스인프라 / 현대엔지니어링 / SK일렉링크) — **선택에 따라 필요 서류가 바뀜**
- 현장명*, 현장주소, 건축물 유형(공동주택/상업시설)
- **계약 주체*** (입주자대표회의 / 관리단 / 건설사) — 노션에 없는 신규 필드. 회의록 종류를 결정
- 총 주차면수, 현장담당자, 현장연락처, 현장이메일

### 실사정보
- 기설치 충전기(없음/있음/확인 불가) — "있음"이면 증빙자료 필수 전환
- 수전방식*(한전불입/모자분리/한전불입+모자분리) — 청구서 필요 여부 결정
- 신설·교체 구분(신규/제자리교체/위치변경교체)
- 기설치 현황(있음일 때 텍스트)

### 계약사항
- 사업구분*(환경부/자체투자/브랜드/…)
- **계약 라인(복수 가능)**: {계약기간(5/7/10), 대수, 구분메모} — 한 현장에 여러 계약.
  예) 속초 ES아뜨리움 = 7년×3대 + 10년×4대. **단가 규칙은 라인별로 따로 지정**
- 특이사항

## 3. 서류 마스터 + 조건부 필수 규칙 ★핵심★

서류는 **번호가 아니라 종류(key)로 다룬다.** ZIP 자동분류가 종류를 판별해 각 칸에 채운다.
해당없는 서류도 칸을 없애지 말고 회색 "해당없음"으로 표시(실수 누락 vs 원래 불필요 구분).

req 값: `m`=필수, `c`=조건부필수, `o`=해당없음. `fee`=영업비 지급조건 서류.

```
key         라벨                        필수 조건
contract    계약서                     항상 m
agreement   합의서                       플러그링크·나이스인프라만 m, 그 외 o
sealuse     직인사용 동의서               항상 m
privacy     개인정보 수집·이용 동의서      항상 m (상시 수집)
apply       전기차 완속충전시설 설치신청서  항상 m
consult     사전현장컨설팅 결과서          항상 m · fee(영업비조건)
photo       사진대지                     PL·NICE는 o, 그 외 m · fee
minutes     회의록                       계약주체=건설사면 c, 그 외 m
                                        └ 라벨: 입주자대표회의→"입주자대표회의 회의록"
                                                관리단→"관리단 회의록"(사업장·상가)
                                                건설사→"회의록(건설사)"
kepcobill   한국전력 전기요금 청구서        수전방식에 모자분리 포함 시 m, 아니면 o
bldgreg     건축물대장                    항상 m
bizreg      사업자등록증                  항상 m
survey      실사보고서                    PL·NICE만 m(xlsx), 그 외 o · fee
legacylog   기설치 충전기 설치이력         항상 m(엑셀). 기설치 없어도 '없음' 확인용 제출
                                        └ 양식 다운로드: /notices/legacy-charger-history.html
legacyev    기설치 증빙자료               기설치=있음이면 m, 아니면 c
checklist2  별지2 사전체크리스트           현대엔지니어링만 m, 그 외 o
```

**중요**: 06 행위신고 업무대행 동의서는 **폐지됨**(더 이상 안 받음).
**중요**: photo와 survey는 상호배타 — PL/NICE는 survey, HEC/SK는 photo. 둘 중 하나만 필수가 됨.

### 접수 차단 규칙
- 필수(m) 서류가 하나라도 없거나 반려 상태면 접수 버튼 비활성.
- consult 또는 (photo|survey)가 없으면 "영업비 지급조건 미달" 경고.

## 4. 검수 흐름 (한백)

- 접수 상태: `recv`(검수 대기) → `fix`(보완 요청) → `ok`(접수 완료)
- **항목별 검수**: 서류 하나만 반려 가능. 반려 시 사유 입력 → 영업사 화면에 그 항목만 "재업로드"로 표시.
  (지금 tally/ZIP 방식은 전체를 반려할 수밖에 없어 영업사가 전부 다시 압축해야 함 — 이걸 개선)
- 필수 서류 다 충족돼야 "접수 완료 처리" 가능.
- **단가 규칙 지정**: 계약 라인마다 규칙 선택. 지정되면 영업비·시공비 계산되어 영업사에게 공개.
  현재 후보 필터: 사업구분 + 수전방식 + 계약기간. (실제로 운영사·건축물유형도 들어가는지 확인 필요)

## 8. 단가 매트릭스 = 접수의 종착점 (중요)
접수에서 한백이 계약 라인마다 "적용 단가 규칙(매트릭스 케이스)"을 고르면, 그 한 번의 선택으로:
- 영업비·시공비·한백마진·턴키단가 확정 (영업사에게 영업비·시공비 공개)
- **기성 1/2/3차 트리거·유형·대당금액도 동시 확정** → settlement 행 생성의 근거
즉 접수 단계의 단가 지정이 이후 정산 전체를 결정한다. 매트릭스 케이스를 정확히 매칭하는 게 핵심.

**매트릭스는 관리자가 직접 관리한다**(SYSTEM_ARCHITECTURE §3-1). 하드코딩 아님.
한백이 관리자 화면에서 케이스를 추가/수정/복제/비활성화. 반기 단가 변경·프로모션 대응.

**★단가 지정은 스냅샷★**: 라인에 케이스를 지정하면 그 시점의 단가·트리거를 계약 라인에 복사한다.
나중에 매트릭스가 수정돼도 이미 지정된 현장 금액은 안 바뀐다(정산 분쟁 방지).
지정 전까지 영업사는 "단가 미지정"으로만 보임.
